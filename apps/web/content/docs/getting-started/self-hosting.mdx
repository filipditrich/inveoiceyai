Invoicey is a Bun + Turborepo monorepo that deploys as a single Next.js app on Vercel. Everything —
web UI, remote MCP endpoint, the Slack agent, PDF rendering — runs from `apps/web`.

## Prerequisites

| Requirement             | Why                                                                         |
| ----------------------- | --------------------------------------------------------------------------- |
| **Node.js 24+**         | Required by the Eve runtime the Slack agent uses                            |
| **Bun 1.3+**            | Package manager and script runner                                           |
| **A Postgres database** | Neon is what the project targets; any Postgres URL works                    |
| **Vercel account**      | For the hosted deployment. Local development needs nothing but the database |

## Local development

```bash
git clone https://github.com/filipditrich/inveoiceyai
cd inveoiceyai
cp .env.example .env.local
bun install
bun db:push
bun dev
```

Environment is read from the **repo root** — `.env` first, then `.env.local` overriding it. This is
deliberate: Drizzle, the standalone MCP server and Next.js all need the same values, and Next only
looks inside `apps/web` by default.

`bun dev` serves the app on `http://localhost:3000`, docs included at `/docs`.

## Minimum viable configuration

Only three variables are genuinely required to boot:

| Variable              | Notes                                                                  |
| --------------------- | ---------------------------------------------------------------------- |
| `DATABASE_URL`        | Postgres connection string                                             |
| `NEXT_PUBLIC_APP_URL` | Public origin. Used for payment links, OAuth callbacks and email links |
| `BETTER_AUTH_SECRET`  | At least 32 characters. Needed **at build time**, not just at runtime  |

Everything else degrades gracefully rather than crashing. Without OAuth credentials there are no
sign-in buttons; without `RESEND_API_KEY` sending fails with a clear error; without a database no
surface works at all. The full list is in
[environment variables](/docs/reference/environment-variables).

<Callout type="warn" title="BETTER_AUTH_SECRET is a build-time dependency">
  `next build` runs with `NODE_ENV=production`, and the auth module throws on
  the default secret at construction time. Any build that imports auth — which
  is all of them — fails without it. Set it in your build environment, not only
  in your runtime environment.
</Callout>

## Deploying to Vercel

The project is a monorepo, so point the Vercel project's root at `apps/web` and let it detect
Next.js.

One non-obvious flag: the Slack agent is built on Eve, which Vercel only recognises behind an
experimental flag.

```bash
VERCEL_USE_EXPERIMENTAL_FRAMEWORKS=1 vercel deploy --prod
```

Without it the build succeeds but `/eve/v1/*` is never generated, and Slack stops working with no
obvious error. If you are not using the Slack integration you can ignore this entirely.

## Verifying a deployment

```bash
curl -sS https://your-host/eve/v1/health
```

Returns `{"ok":true,"status":"ready",...}` when the agent runtime is up. For MCP, the endpoint
should reject an unauthenticated request:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://your-host/api/mcp
```

A `401` here is the correct answer — it means the bearer gate is active. A `200` would mean
something is very wrong.
