Claude Code connects to MCP servers from the CLI, so the same tools available in
[Cursor](/docs/integrations/cursor) work here.

## Adding the server

```bash
claude mcp add --transport http --scope user invoicey \
  https://invoicey.app/api/mcp \
  --header "Authorization: Bearer YOUR_API_KEY"
```

Verify:

```bash
claude mcp list
```

<Callout title="Prefer user scope">
  `--scope project` writes to `.mcp.json` in the repository, which is checked in
  and shared. A bearer token does not belong there. User scope keeps it in your
  own config.
</Callout>

## Using it

Tools appear as `invoicey` tools in any session:

> Check my connected workspace and issuer, then look up NFCtron in ARES and prepare a draft for
> 32 hours of consulting at 1,800 CZK per hour, due in 14 days. Ask for missing dates, VAT and
> document language. Show the draft before issuing.

And for follow-ups:

> List unpaid invoices and tell me which are overdue.
>
> Mark 20260012 as paid and email the client a copy with the ISDOC attached.

Review the invoice and explicitly confirm issuing, sending or recording payment. Host approval controls may vary; the connected workspace permissions still apply.

## Workspace issuer first

Add your business in Invoicey and choose its default issuer before drafting. The connected tools
load the seller server-side and do not accept issuer or template preset IDs on `create_invoice`.
If the workspace has no usable issuer, drafting fails with setup guidance. See
[issuer setup](/docs/guides/issuers#presets-for-automation).

## Troubleshooting

<Accordions>

<Accordion title="Unauthorized on every call">
  The key was revoked, mistyped, or truncated when copied. Personal keys are
  shown once — if you are not certain you have it intact, create a new one under
  **[Workspace → API keys](/settings/workspace/api-keys)**.
</Accordion>

<Accordion title="The server shows as failed">
  Run `claude mcp list` for status, then confirm the URL and bearer header are
  intact.
</Accordion>

</Accordions>
