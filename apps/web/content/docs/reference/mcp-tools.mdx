## lookup_business

Look up a Czech economic subject by IČO via ARES. Returns draft client fields — without an `id`,
which is assigned when saved.

<TypeTable
  type={{
    ico: { type: "string", description: "Eight-digit IČO", required: true },
  }}
/>

Prefer this over `search_business` once the IČO is known.

## search_business

Search by company name (obchodní jméno). Returns matches with IČO and structured address; follow up
with `lookup_business` on the chosen IČO.

<TypeTable
  type={{
    query: {
      type: "string",
      description: 'Company name fragment, e.g. "NFCtron a.s."',
      required: true,
    },
    limit: { type: "number", description: "1–20. Default 5" },
  }}
/>

## create_invoice

Assemble a draft, validate it against the schema, and render the PDF and ISDOC. Returns the validated
invoice, base64 PDF and ISDOC XML — or the list of validation issues.

<TypeTable
  type={{
    draft: {
      type: "object",
      description:
        "Partial invoice: meta, client, vat, payment, items. Issuer is ignored.",
    },
  }}
/>

<Callout type="warn" title="The issuer is locked server-side">
  Any `issuer` inside `draft` is **ignored**. The issuer is the workspace
  default (`is_default`). If the workspace has no issuer, the tool fails — a
  demo issuer is never written to Neon. A model cannot put a bank account or IČO
  on your invoice.
</Callout>

Do not pass `issuerPresetId` or `templatePresetId` — those arguments do not exist.

Nothing is silently defaulted. Omitting `duzp` is an error, not an invoice dated today. Field rules:
[invoice schema](/docs/reference/invoice-schema).

## send_invoice_email

Emails an issued invoice with the PDF and, by default, the ISDOC. Needs `RESEND_API_KEY` as well as a
database.

<TypeTable
  type={{
    id: { type: "string", description: "Invoice row UUID", required: true },
    to: {
      type: "string",
      description: "Recipient. Defaults to the client contact email when set",
    },
    cc: { type: "string[]", description: "Additional recipients" },
    subject: { type: "string", description: "Overrides the issuer default" },
    coverText: { type: "string", description: "Custom cover body" },
    attachIsdoc: {
      type: "boolean",
      description: "Defaults to the issuer setting, normally true",
    },
  }}
/>

<Callout type="warn">
  Pass `to` explicitly when the client has no contact email. Do not let an
  assistant guess an address — this tool sends real mail to real people.
</Callout>

### save_preset

Creates or updates. Omit `id` to create.

<TypeTable
  type={{
    id: { type: "string", description: "Omit to create a new preset" },
    kind: { type: "'issuer' | 'invoice_template'", required: true },
    name: { type: "string", description: "1–120 chars", required: true },
    data: {
      type: "object",
      description: "An IssuerSnapshot, or a partial invoice draft",
      required: true,
    },
  }}
/>

For `kind: "issuer"`, `data` must be a complete issuer snapshot — name, IČO, address, bank account,
VAT flag, contact email. For `kind: "invoice_template"`, any partial draft: `meta`, `vat`, `payment`,
`items`.

## Storage

Presets are stored in your Invoicey workspace database and available to every MCP session that uses
your personal API key.

## Not available over MCP

- Creating issuers or clients — web UI only; MCP consumes them via presets
- [Historical import](/docs/guides/importing-history) — web only, by design
- Unmarking an invoice as paid
- Cancelling an invoice
