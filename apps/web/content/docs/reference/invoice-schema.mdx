title: Invoice schema reference
description: Every field of the invoice payload, and the rules it must satisfy.
---

The contract every surface validates against. Useful when writing a payload by hand, debugging a
rejected automated call, or working out what an error message means.

Conceptual background: [an invoice is data](/docs/concepts/invoice-as-data).

## Top level

```ts
{
  meta:     InvoiceMeta,
  issuer:   IssuerSnapshot,
  client:   ClientSnapshot,
  vat:      InvoiceVat,
  payment:  Payment,
  items:    InvoiceItem[],   // at least 1
  totals:   Totals,
  notes?:   string,          // max 2000
  customization?: InvoiceCustomization,
}
```

```ts
Address = {
  street:  string,  // 1–200
  city:    string,  // 1–100
  zip:     string,  // /^\d{3} ?\d{2}$/
  country: 'CZ',
}

BankAccount = {
  accountNumber: string,  // /^(?:\d{1,6}-)?\d{1,10}\/\d{4}$/
  iban:          string,  // /^CZ\d{22}$/
  bic?:          string,  // 8 or 11 chars
}
```

      type: "string",

        "8 digits. Optional — foreign clients and natural persons may have none",
    },

    address: { type: "ClientAddress", required: true },
    contactEmail: {
      type: "string",
      description: "Needed to email without typing a recipient",
    },
  }}
/>

`ClientAddress` is looser than the issuer's: `country` is any ISO 3166-1 alpha-2 code and `zip`
accepts non-Czech formats, so cross-border invoicing fits.

## vat

<TypeTable
  type={{
    mode: { type: "'regular' | 'reverse_charge' | 'oss'", required: true },
    suppliesAbroad: { type: "'none' | 'eu' | 'non_eu'", required: true },
    legalNote: {
      type: "string",
      description: "Printed on the PDF. Max 500 chars",
    },
    localReverseChargeCode: {
      type: "string",
      description: "PDP číselník code. Required when mode is reverse_charge",
    },
  }}
/>

Cross-field rules:

- `reverse_charge` → every item's `vatRate` must be `0`, and `localReverseChargeCode` is required.
- `oss` with `suppliesAbroad: 'none'` is invalid — OSS is cross-border by definition.
- `issuer.vatPayer === false` → mode must be `regular` and every `vatRate` must be `0`.

<Callout type="warn">
  `localReverseChargeCode` is a číselník code such as `4`, not a paragraph
  reference. `92e` here produces an ISDOC importers reject. The §-reference
  belongs in `legalNote`.
</Callout>

`bankAccount` defaults from the issuer at issue time, but may be overridden — an issuer with several
accounts can invoice from a different one per invoice.

Only `transfer` with a bank account produces a [payment QR](/docs/outputs/payment-qr).

## items

At least one required.

<TypeTable
  type={{
    position: {
      type: "number",
      description: "1-indexed, dense",
      required: true,
    },
    description: { type: "string", description: "1–500 chars", required: true },
    quantity: { type: "number", description: "Positive", required: true },
    unit: {
      type: "string",
      description: "Free-form: 'ks', 'h', 'měs.'",
      required: true,
    },
    unitPriceWithoutVat: {
      type: "number",
      description: "Non-negative",
      required: true,
    },
    vatRate: {
      type: "number",
      description: "0, 12, 21, or any integer 0–100",
      required: true,
    },
    lineSubtotal: { type: "number", required: true },
    lineVat: { type: "number", required: true },
    lineTotal: { type: "number", required: true },
  }}
/>

Per-line invariants, recomputed server-side:

```ts
lineSubtotal === round2(quantity * unitPriceWithoutVat);
lineVat === round2((lineSubtotal * vatRate) / 100);
lineTotal === round2(lineSubtotal + lineVat);
```

## totals

```ts
Totals = {
  subtotal:      number,
  vatBreakdown:  { rate: number, base: number, vat: number }[],
  vatTotal:      number,
  total:         number,
}
```

Invariants:

- `subtotal === sum(items.lineSubtotal)`
- one `vatBreakdown` entry per distinct rate, with `base` the sum of that rate's subtotals
- `vatTotal === sum(vatBreakdown.vat)`
- `total === subtotal + vatTotal`

`vatBreakdown` is what the PDF prints as _Rekapitulace DPH_.

<Callout>
  You must supply totals — they are not optional — but the server recomputes and
  compares them. A mismatch aborts the issue. Treat the values you send as a
  checksum, not as the source of truth.
</Callout>

## customization

```ts
{
  accentColor: 'neutral' | 'blue' | 'green' | 'amber' | 'rose' | 'violet',  // default 'neutral'
  showStamp:     boolean,  // default false
  showSignature: boolean,  // default false
}
```

Deliberately narrow. There is one PDF template, not a template editor.
