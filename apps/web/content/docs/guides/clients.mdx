Clients are the people or businesses you invoice. They live in a shared registry per workspace, so you enter
each one once and reuse it.

## ARES lookup

[ARES](https://ares.gov.cz) is the Czech public business registry. Invoicey queries it directly, so
you rarely type a client's details by hand.

**By IČO** — enter 8 digits and Invoicey fetches the subject and maps:

| ARES field      | Becomes                                   |
| --------------- | ----------------------------------------- |
| `obchodniJmeno` | Name                                      |
| `ico`           | IČO                                       |
| `dic`           | DIČ, only if it is well-formed            |
| `sidlo`         | Address — street, house number, city, PSČ |

**By name with an assistant** — ask an [MCP assistant](/docs/integrations/mcp) to search the company
name and confirm the matching IČO. In the web client form, enter the IČO or use manual entry.

Successful lookups are cached for 24 hours per IČO, reducing unnecessary calls to the public API.

<Callout title="ARES never supplies an email">
  The registry has no contact email, so that field is always yours to fill. It
  is worth doing: without it, every invoice send requires typing the recipient
  manually.
</Callout>

### When lookup fails

Four distinct outcomes, all reported plainly rather than as a generic failure:

| Outcome          | Meaning                                                           |
| ---------------- | ----------------------------------------------------------------- |
| Not found        | No subject with that IČO — check the digits                       |
| Invalid response | ARES answered with something unparseable. Rare; usually transient |
| HTTP error       | ARES is down or rate-limiting                                     |
| Invalid IČO      | Not 8 digits — rejected before any request is made                |

Every path falls back to manual entry. ARES being unavailable never blocks you from invoicing.

## Required fields

A name and complete address are required. IČO is optional for a client; when supplied, it must have
8 digits. Czech DIČ uses `CZ` plus 8–10 digits; the client field also accepts foreign VAT identifiers.
Choose the two-letter country code and use the client’s postal code. ARES lookup applies to Czech IČO.

DIČ is optional in general but **required** when you invoice that client under
[reverse charge](/docs/concepts/czech-vat) — the schema enforces it at issue time, so a missing DIČ
surfaces as a blocked issue rather than an invalid invoice in the wild.

## Foreign clients

Enter a foreign client manually, including the country code and postal address. A Czech IČO is not
required. In the invoice builder you can choose CZK, EUR or USD, and select Czech or English document
language independently of the app language. Payment QR is available only for CZK invoices.

Review VAT mode and cross-border settings for the transaction before issuing; adding a foreign
address does not determine those settings for you. See [VAT settings](/docs/concepts/czech-vat).

## Editing and deleting

Edits affect **future** invoices only. Invoices already issued to a client carry a frozen
[snapshot](/docs/concepts/snapshots) of how they looked at issue time.

Invoicey blocks deletion when a client is referenced by an invoice or recurring template, including
a draft. You can delete an unused client. Editing the registry does not rewrite the frozen details
on an issued invoice.
