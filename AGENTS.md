## Learned User Preferences

- Capture product scope, specs, and architecture as maintained Markdown under `docs/` (split files, phased plans) instead of one giant in-chat plan.
- When executing an attached Cursor plan: do not modify the plan file; use existing todos only, mark items in progress, avoid creating duplicate todo lists.
- Position Invoicey as Czech-first invoicing automation (tagline like “Automatizace faktur” / “Invoice automation”); avoid “česká faktura/fakturace” pride marketing—keep Czech standards (ARES, DPH, ISDOC) as capabilities. Keep README/top-level docs polished.
- Solo workflow: prefer `/worktree` for feature work, verify locally (e.g. `typecheck`, `lint`, `test`, `build`), commit/push to `main`, then `/delete-worktree`; prefer logically scoped conventional commits over one bulk “finalize” commit when splitting is natural.
- Prefer AI-driven invoice creation (validated `InvoiceSchema` JSON → PDF/ISDOC) via MCP, Slack/Eve, and in-app web draft—not a heavy invoice builder UI; meter workspace AI usage in tokens with transparent per-product (web/slack/mcp) tracking.
- Prefer hosting remote MCP and Eve on the existing `@invoicey/web` Vercel app over separate hosts (e.g. Fly.io).
- Web auth is Better Auth OAuth-only (Google/GitHub); gate MCP/Eve with API keys. Prefer deepening account security (provider link/unlink, sessions/revoke, trusted devices) over reintroducing password auth.
- Before commit/PR on agent-written feature branches, run deslop (remove AI slop; keep behavior).
- For Eve/Slack agent invoice drafts: teach required schema fields in instructions, skills, and tool descriptions; do not silently default missing required fields (especially issuer/dodavatel) in normalizers—ask or confirm in Slack HITL, with a prefilled suggestion when assuming.
- Historical issued-invoice import is web bulk-only (no MCP/Slack tooling); track provenance/source (Invoicey version, fakturaonline, other Czech issuers, custom) with list filters; show hosted issued PDFs inline on detail.
- Prefer clear multi-currency, with/without-VAT, and per-invoice document language (`cs`/`en`) UX (presets over ambiguous free-input; not dual-label bilingual PDFs); issuer branding via image upload (not URL-only).
- Keep public marketing `/` reachable when logged in (do not force-redirect authenticated users into the app); first-login onboarding should guide creating the first issuer (ARES-first, Czech account→IBAN suggest/validate, optional parse-from-uploaded-invoice bootstrap, skippable defaults), with issuer settings split into section routes/tabs.

## Learned Workspace Facts

- Root package name is `invoicey`; monorepo uses Bun workspaces and Turborepo (`apps/*`, `packages/*`). Phased delivery lives in `docs/roadmap.md`, tied to `.cursor/plans/` with exit-criteria checklists.
- Default web entry: `bun dev` runs `@invoicey/web` via Turbo; `bun db:push` runs Drizzle against `@invoicey/db`; `packages/db/drizzle.config.ts` and `apps/web/next.config.ts` load repo-root `.env` then `.env.local` (override). Eager DB client is `@invoicey/db/client` (requires `@invoicey/env`); optional MCP path uses `tryCreateDbFromEnv()`. Seeded workspace UUID: `INVOICEY_DEFAULT_WORKSPACE_ID` / `DEFAULT_WORKSPACE_ID`. Put `DATABASE_URL` in `apps/web/.env.local` when Next imports the client. Run `bun run test` at repo root (Vitest/Turbo).
- `apps/web` targets Next.js 16 and TypeScript 6 in living docs; some ADR titles may still say Next.js 15. App list pages use ReUI Data Grid + Filters (search/sort/filter); prefer sticky table headers on long lists.
- Domain package `@invoicey/invoice-core`: subpath `@invoicey/invoice-core/schema` for client-safe Zod types; full entry includes PDF/ISDOC/render. `renderInvoicePdf` returns ISDOC.PDF (visual page + embedded `invoice.isdoc`, PDF/A-3b scaffolding); standalone `renderIsdoc` remains. `IssuerSnapshotSchema` requires `contactEmail`. Lifecycle display (fakturaonline parity): `@invoicey/invoice-core/status-display` (`resolveDisplayStatus`; Future wins over Overdue); web filters/badges and MCP summaries use `displayStatus` (`docs/domain/status-engine.md`).
- Conventional commits via `commitlint.config.mjs` (path scopes like `apps/web` / `packages/db`, short aliases, meta: `docs`, `deps`, `ci`, `config`, `release`, `git`, `security`, `i18n`). Husky: `commit-msg` → commitlint; `pre-commit` → lint-staged (Prettier; blocking `eslint --fix` for `apps`/`packages`); `pre-push` → `bun run typecheck`. Interactive commits: `bun run commit`. Bypass with `--no-verify` or `HUSKY=0` when needed. Releases: `semantic-release` on `main`.
- Web i18n: `next-intl` with UI locales `cs` + `en` (cookie `NEXT_LOCALE`, Accept-Language fallback; no `[locale]` URL prefix). Catalogs `apps/web/locales/{cs,en}.json` typed via `AppConfig` + `createMessagesDeclaration`. Docs MDX stay English. Amounts/dates via locale-aware `lib/format` + next-intl formatters. Invoice PDF/ISDOC labels and client-facing invoice emails follow per-invoice `meta.language` (`cs` | `en`, ADR 0028)—orthogonal to UI locale; dual-label bilingual PDFs are out of scope (ADR 0012 Czech-only language superseded).
- Production host is `https://invoicey.ditrich.me` (Vercel project `inveoiceyai-web`): web app, remote MCP at `/api/mcp`, Eve at `/eve/v1/*`. Set `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL` to that host (not `*.vercel.app`) so sitemap/robots/metadata stay correct. Transactional email via Resend + `@invoicey/emails`; From domain is `invoicey.ditrich.me` (`invoices@` + “Name via Invoicey” for invoice mail; `noreply@` + plain display name for system mail).
- Better Auth (Plan 14): OAuth-only server in `apps/web/lib/auth/`; workspaces are Better Auth organizations (`session.activeOrganizationId` = `workspace_id`, ADR 0019). Plan 20: sidebar workspace switcher/create; switching updates `activeOrganizationId` and `users.defaultWorkspaceId`. Builds that import auth need `BETTER_AUTH_SECRET` at build time. Platform admin (Plan 18 / ADR 0024): `users.platform_role` + `requirePlatformAdmin()` gate `/admin` (cross-tenant metrics/lists); bootstrap via `INVOICEY_PLATFORM_ADMIN_EMAILS` or `packages/db/scripts/grant-platform-admin.ts` — not a workspace org role. Workspace invites: Better Auth org invitations (`/settings/members`, `/invite/[id]`, 48h expiry). Product referrals (Plan 19 / ADR 0025): personal `/r/[code]` + `invoicey_ref` cookie; signup attribution only (`users.referred_by_user_id` + `referral_events`) — never auto-joins a workspace.
- Eve Slack agent (Plan 13b): `apps/web/agent/` via `withEve()`; Connect Slack → `/eve/v1/slack` (`connectSlackCredentials("slack/invoicey")`); HTTP Bearer `EVE_API_KEY` or `MCP_API_KEY`. Slack callers must be linked to an Invoicey user+workspace (`slack_identities` / `slack_link_codes`; one-shot `/slack/link/[code]` DMed, never posted in channels); unlinked users and tools fail closed. Tools wrap `@invoicey/invoice-tools` + `/ops`. Requires Node 24+ and `ai` ^7; prod needs `VERCEL_USE_EXPERIMENTAL_FRAMEWORKS=1`. Setup: `docs/specs/slack-eve.md` / ADR 0020; in-app MCP/Slack setup guides live on the security settings pages.
- MCP (Plan 12a/12b): local stdio `@invoicey/mcp`; shared registration `@invoicey/invoice-tools/mcp`; remote `/api/mcp` via `mcp-handler` + `MCP_API_KEY` (fails closed when unset). Presets: Neon when `DATABASE_URL` is set, else file (`INVOICEY_PRESETS_PATH`); force file with `INVOICEY_PRESETS_BACKEND=file`. Plan 12b: `list_invoices` / `get_invoice` / `mark_invoice_paid` with `status` + `displayStatus`. Web server actions that call `@invoicey/invoice-tools/ops` must pass `workspaceId` from `requireWorkspace()` (do not rely on the default workspace env alone). See `docs/specs/mcp.md`.
- Workspace AI tokens (Plan 21 / ADR 0026): `ai_token_balances` + `ai_usage_events` (gifted/monthly/purchased; debit monthly→gifted→purchased); in-app draft at `/invoices/ai`; usage UI in workspace settings. Web AI uses Vercel AI Gateway (`AI_GATEWAY_API_KEY`, model `INVOICEY_AI_MODEL` default `openai/gpt-4o-mini`)—same stack as Eve. Apply `packages/db/sql/2026-08-12-ai-token-usage.sql` (or `bun db:push`) when balances are missing.
- UploadThing stores issuer assets (including branding image uploads) and invoice PDF/ISDOC artifacts (`UPLOADTHING_TOKEN`). Issued invoices persist `pdf_url` / `isdoc_url` and should be served/shown inline rather than regenerated; imports set `artifacts_immutable` + provenance (Plan 15, ADR 0021, `/invoices/import`) and dedupe clients by IČO (and name).
- Recurring drafts (Plan 10 / ADR 0027): web-only HITL. Cron `/api/cron/recurring-drafts` inserts a draft (live issuer/client snapshots); user issues/sends. Apply `packages/db/sql/2026-08-12-plan10-recurring.sql` (do not unattended `db:push`). No MCP/Eve tools in v1.
